The iframe below loads a genuinely different origin (https://example.com) — the browser's same-origin policy means the outer page's OWN JavaScript cannot read iframe.contentDocument (it's null / throws). Real automation tools generally CAN still read frame content because their frame APIs operate at the CDP/browser-engine level, not through the outer page's JS context — this scenario tests whether each tool's normal selector/read path actually does that, not whether it's theoretically possible.
