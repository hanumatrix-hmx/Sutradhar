## Deviations (each explained)
1. **Per-harness fresh ISO** instead of the single continued `Sgt` (plan 8: "continuation form"): several harnesses assert a clean state dir (S6 uses fresh `st<k>` dirs; S4/S7 own `state`), so each run created `Sgt`/`Ngt` fail-closed, ran the harness unmodified (sha256 `logs/item8-harness-sha*.txt` equal to S8's `harness.sha256`), checked leftovers, and used the guarded delete (same method S8 used and the auditor accepted). The scenario suite (8h) did use the continuation form of one `Sgt`.
2. **8h without the isolated HOME.** Plan: `USERPROFILE`/`HOME` set to `$SP/Sgt/home`. Attempt 1 did that and every scenario failed at navigation in ~12 s (`scenario-attempt1-invalid/`, all 14 CLI scenarios): Chrome does not start on this machine when `USERPROFILE` is relocated (reproduced by hand: `Error: Timed out waiting for Chrome to start`; the same nav with the real USERPROFILE succeeds). That run is kept only as the record of the deviation. The 0.6.1-style precheck was then done: the runners write only under `os.tmpdir()` (the ISO), `tools/scenario-suite/results` (restored) and, in `run-cli` UC-03 / `run-sdk` UC-03, a named profile under the REAL `~/.sutradhar/profiles` (`ProfileManager` default `os.homedir()`), which escapes the ISO. So `run-cli` and `run-sdk` ran with `SCENARIO_FILTER` = every scenario except UC-03 (13 of 14; `SCENARIO_OUTPUT_PATH` pointed at the tracked baseline name so ci-gate reads fresh data); `run-mcp` has no profile use and ran whole (14). UC-03 on CLI/SDK is therefore NOT covered by this gate (the profile/launch paths it exercises were not touched by 0.6.2; the CLI/SDK/MCP live harnesses above cover the changed surfaces). The runners' own CLI children do not forward stderr, so there are no `[cleanup]` lines to path-check for 8h; isolation evidence there is the guard line, the final CIM query and the unchanged real TEMP list.
3. **8c consumer attempt 1 failed the harness's churn-validity check once** (`s4-consumer`: 11 PASS, 1 FAIL `L1 churn really happened`, `recreated=7256,NaN,...`): one `eval window.__recreated` call exited 1 with `a unknown dialog is open ... the dialog check could not finish in time; try the command again` (the 0.6.0 dialog guard timing out under load while four iframes were being replaced every 25 ms; `logs-s4-consumer/007-eval.stderr.log`). All product outcomes of that run were clean (L1 0/5 detached, L2 5/5, L3 0/30, L4 0/5). Re-ran once (`s4-consumer-run2`): 12 PASS. Recorded as a flake of the measurement, not a product pass-through; if the orchestrator wants a stricter reading, the first run counts as one failure of 8c and the gate escalates (plan section 3 rule 2 is about audited items, not harness reruns).
4. The matrix `llm` entry (item 5) is the one non-pass; see the table. I continued with 6-9 and S11b after it (no product change was involved) so the orchestrator has the full evidence set; the release is NOT cleared by S11.
