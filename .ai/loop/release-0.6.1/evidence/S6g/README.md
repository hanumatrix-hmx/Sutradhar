- `packages/cli/tests/unit/close-session.spec.ts`: the old "never-throws" test is split (F1): the kill half is kept unchanged in substance (renamed, plus: no warning, debug-only kill-error line);

## Deviations (all disclosed)
1. **P5 ISO name.** The harness ISO is `$SP/S6gi` (4 characters), not `S6g-tmp`: HEAD's profile name is 34 characters, so `S6g-tmp` gave `--user-data-dir` = 203 > 200 and the harness's own P5 check failed on the first attempt (`ab/attempt1-iso-name-too-long/`). The guarded delete for it is therefore the exact-path form (`ab/iso-rm.sh`), not the `S[0-9]*-tmp` case pattern.
2. **Scratch accident, own files only.** My first `iso-rm.sh` had `ISO=$SP/S6g`, which was also my scripts scratch dir; it deleted my own helper copies there (the evidence copies of every script and defs file were already in this directory). Nothing else was touched (no repo file, no other session's dir; `S6g-ctl` intact, sha re-verified `48c1756c...`).
3. **Control binary resolution.** The copied `bff46db` `cli-bin.js` could not resolve `puppeteer-core` from the scratchpad (first ctl attempt: `ERR_MODULE_NOT_FOUND`, `ab/attempt1-iso-name-too-long/ctl-resolution-fail/`). A directory junction `$SP/S6g-ctl/node_modules` -> `$WT/packages/sutradhar/node_modules` gives it the same puppeteer-core (25.5.0) as HEAD. The junction is removed (as a link) at the end of the task.
4. `ab/run-v060-*` runs have no `[cleanup]` lines (0.6.0 has no debug seam), so the path-check applies to head/ctl/mutants only.
5. In the swallow runs (control, mutants) the CLI exits 0 and a state.json that still records the dead `chromePid` remains; the harness (not a CLI command) deletes it, as in every run.
